# 1.9.0 — Separate metadata panel and verified upgrade identity

## Requested scope

Reviewed the conversation after 1.8.5. The final instruction overrides earlier layout proposals: **keep the existing screen exactly as it is, except detach Raw Model Metadata below the Advanced Chat Usage block**. Sync stays at the top. No extra KPI block, quota redesign, chart/slider rearrangement, colour change or acquisition-policy change is included.

## Delivered

- Raw Model Metadata is now a direct dashboard sibling after the usage block, with the existing 14px inter-block gap.
- Native details disclosure starts closed. An explicit localized Expand/Collapse button mirrors the existing Sync control. Keyboard activation is retained.
- The existing table, selected-range grouping and CSV export are retained. Opening the panel does not trigger backend requests.
- Version labels and diagnostics filename are 1.9.0; stable internal DOM identifiers remain unchanged.
- The exact **existing 1.8.5 public manifest key** is retained. Contrary to an earlier chat explanation, the shipped 1.8.5 ZIP already contained it. It is not generated anew in 1.9.
- Existing complete, paused and partial index detection is retained and covered by regression tests. Users with readable local data bypass onboarding; no additional welcome screen is introduced.
- README now describes in-place Developer Mode upgrades, backup/import, and the uninstall boundary. A stable ID cannot recover storage deleted by Remove.
- Earlier release notes moved verbatim to `archive/release-notes/`. Their statements are historical, not current validation evidence.
- Repository runtime synchronized from the actual distributed 1.8.5 source; old `main` was 1.7.3.

## Preserved

All 1.8.5 history acquisition, throttling, Project rotation, identity/account scoping, backup format, settings, language/theme, numeric reference limits and classification behaviour remain intact. `api.js`, `bridge.js`, `limits.js`, `live.js`, `policy.js`, `sync.js` and `tasks.js` are byte-identical to the supplied 1.8.5. `core.js` and `i18n.js` only have release-label changes.

## Validation boundary

Current results are generated by `python tools/test.py`; the new checks cover separate DOM hierarchy, collapse/expand/keyboard behaviour, table/CSV/range preservation, localization and complete/paused returning indexes. Public-key identity is checked against the supplied 1.8.5 build. Native extension-page testing was attempted but blocked by this environment; it is **not reported as passed**. ChatGPT backend requests and browser storage/locks in the integration suites are mocked. Orion/iPad has not been device-tested.
